The COUNT function is your first tool for data analysis. It answers the question: "How many records do I have?"

What is COUNT?

COUNT is an aggregate function that returns the number of rows that match a specified condition. Think of it as a counter that tallies up your data.

Three Ways to Use COUNT

SyntaxWhat It CountsUse When
COUNT(*)All rows (including NULLs)You need the total number of records
COUNT(column)Non-NULL values in that columnYou want to know how many values exist
COUNT(DISTINCT column)Unique values onlyYou need to find variety in your data

Example 1: Basic Count

Task: Count all people in the database

SELECT COUNT(*) AS count_records
FROM people;

Sample Output:

count_records
8397

Example 2: Multiple Counts

Task: Count languages and countries in the films table

SELECT
    COUNT(language) AS count_languages,
    COUNT(country) AS count_countries
FROM films;

Sample Output:

count_languagescount_countries
49575000

Notice: country has more records because some films have NULL language values.

Example 3: Distinct Count

Task: How many unique countries are in our database?

SELECT COUNT(DISTINCT country) AS count_distinct_countries
FROM films;

Sample Output:

count_distinct_countries
64

Pro Tip

Use COUNT(*) when you need total rows, and COUNT(column) when you want to exclude NULL values!

Logical Operators Explained

Logical operators let you combine multiple conditions:

  • AND - ALL conditions must be TRUE (narrows results)
  • OR - AT LEAST ONE condition must be TRUE (broadens results)
  • BETWEEN - Value falls within a range (inclusive)

NULL represents missing or unknown data. Learn how to find and filter NULL values properly!

What is NULL?

NULL means "no value" or "unknown". It's not zero, not empty string - it's the absence of data.

CRITICAL RULE

  • ✗ NEVER use = NULL or <> NULL
  • ✓ ALWAYS use IS NULL or IS NOT NULL

  • Questions like "how many films per country?"
  • Any time you use aggregate functions with specific categories

HAVING is like WHERE, but for groups! It filters grouped results after GROUP BY has done its work.

Understanding HAVING

HAVING filters groups created by GROUP BY, just like WHERE filters individual rows. Use HAVING when you need to filter based on aggregate function results (COUNT, SUM, AVG, etc.).

WHERE vs HAVING - The Big Difference

AspectWHEREHAVING
FiltersIndividual rowsGrouped results
TimingBefore groupingAfter grouping
Works withColumn valuesAggregate functions
ExampleWHERE budget > 1000000HAVING AVG(budget) > 1000000
Can use aggregates?✗ No✓ Yes

Complete Execution Order

  1. FROM - Get data from table
  2. WHERE - Filter individual rows (before grouping)
  3. GROUP BY - Group the filtered rows
  4. HAVING - Filter groups (after grouping) ← You are here
  5. SELECT - Choose columns to display
  6. ORDER BY - Sort results
  7. LIMIT - Restrict count

Example 1: Filter by Count

Task: Find countries with more than 10 different certifications

SELECT country, COUNT(DISTINCT certification) AS certification_count
FROM films
GROUP BY country
HAVING COUNT(DISTINCT certification) > 10;

France11

Example 2: Filter by Average

Task: Countries with average budget over 1 billion

SELECT country, AVG(budget) AS average_budget
FROM films
GROUP BY country
HAVING AVG(budget) > 1000000000
ORDER BY average_budget DESC;

Sample Output:

countryaverage_budget
USA2500000000.00
UK1200000000.00

Example 3: Using Both WHERE and HAVING

Task: USA films by year, only years with 50+ films

SELECT release_year, COUNT(*) AS film_count, AVG(budget) AS avg_budget
FROM films
WHERE country = 'USA' -- Filter rows FIRST
GROUP BY release_year
HAVING COUNT(*) > 50 -- Then filter groups
ORDER BY release_year DESC;

201712872000000

WHERE filters to USA first, then GROUP BY counts per year, then HAVING filters to years with 50+ films

Common Mistake: Using WHERE for Aggregates

-- ✗ WRONG: Can't use aggregate in WHERE
SELECT country, COUNT(*) AS film_count
FROM films
WHERE COUNT(*) > 100 -- ERROR!
GROUP BY country;

-- ✓ CORRECT: Use HAVING for aggregate conditions
SELECT country, COUNT(*) AS film_count
FROM films
GROUP BY country
HAVING COUNT(*) > 100;

Quick Decision Guide

  • Filtering individual rows? Use WHERE
  • Filtering grouped results? Use HAVING
  • Using aggregate functions? Use HAVING
  • Need both? Use WHERE first, then HAVING

Try it yourself

Find languages with average duration over 120 minutes:

FROM films
WHERE duration IS NOT NULL
GROUP BY language
HAVING AVG(duration) > 120
ORDER BY avg_duration DESC;

SQL doesn't execute in the order you write it! Understanding execution order helps you write better queries and debug errors.

The Truth About SQL Execution

When you write a SQL query, you write clauses in a specific order (SELECT, FROM, WHERE...). But SQL executes them in a completely different order! This is critical to understanding why certain things work and others don't.

Complete Execution Order

OrderClauseWhat It DoesOutput
1FROMGet data from table(s)All rows from table
2WHEREFilter individual rowsFiltered rows
3GROUP BYGroup rows togetherGrouped data
4HAVINGFilter grouped resultsFiltered groups
5SELECTChoose columns to displaySelected columns
6ORDER BYSort resultsSorted results
7LIMITRestrict number of rowsFinal output

Visual Execution Flow

  1. 1. FROMGet all data from table(s)
  2. 2. WHEREFilter individual rows
  3. 3. GROUP BYGroup filtered rows
  4. 4. HAVINGFilter groups
  5. 5. SELECTChoose columns to show
  6. 6. ORDER BYSort the results
  7. 7. LIMITTake only N rows

Example: Step-by-Step Execution

Query: Find top 5 countries with most films released after 2010

SELECT country, COUNT(*) AS film_count -- Step 5
FROM films -- Step 1
WHERE release_year > 2010 -- Step 2
GROUP BY country -- Step 3
ORDER BY film_count DESC -- Step 6
LIMIT 5; -- Step 7

Execution Steps:

StepActionResult
1. FROM filmsLoad all records from films table5,000 rows
2. WHERE year > 2010Keep only films after 20101,823 rows
3. GROUP BY countryGroup films by country64 groups
4. (no HAVING)Skip - not used in this query64 groups
5. SELECT country, COUNT(*)Choose columns to display64 rows, 2 columns
6. ORDER BY film_count DESCSort by count, highest first64 sorted rows
7. LIMIT 5Take only top 55 rows

Why This Order Matters

ConceptWhy It Works / Doesn't Work
Can't use column aliases in WHEREWHERE runs before SELECT, so aliases don't exist yet
Can use column aliases in ORDER BYORDER BY runs after SELECT, so aliases are available
Can't use aggregates in WHEREAggregates are calculated during GROUP BY, which runs after WHERE
Can use aggregates in HAVINGHAVING runs after GROUP BY, so aggregates are ready
LIMIT is very efficientRuns last, so SQL stops as soon as it has enough rows

Common Mistakes Due to Execution Order

-- ✗ WRONG: Can't use alias in WHERE (alias created in SELECT)
SELECT duration / 60.0 AS hours
FROM films
WHERE hours > 2; -- ERROR! "hours" doesn't exist yet

-- ✓ CORRECT: Use original column in WHERE
SELECT duration / 60.0 AS hours
FROM films
WHERE duration > 120; -- Works! Using original column

-- ✓ ALSO CORRECT: Can use alias in ORDER BY
SELECT duration / 60.0 AS hours
FROM films
ORDER BY hours; -- Works! ORDER BY runs after SELECT

Memory Trick

Think of it as a data pipeline:
  1. Get raw data (FROM)
  2. Filter it (WHERE)
  3. Group it (GROUP BY)
  4. Filter groups (HAVING)
  5. Format for display (SELECT)
  6. Arrange nicely (ORDER BY)
  7. Trim excess (LIMIT)

Quick Knowledge Check

Question 1: What's the difference between COUNT(*) and COUNT(column)?

Click to reveal answer
Answer: COUNT(*) counts all rows including NULLs, while COUNT(column) only counts non-NULL values in that column.

Question 2: How do you find values that contain "sql" anywhere in the text?

Click to reveal answer
Answer: WHERE column LIKE '%sql%'

The % wildcard matches zero or more characters before and after "sql".

Question 3: What's wrong with: WHERE budget = NULL?

Click to reveal answer
Answer: You can't use = with NULL. The correct syntax is WHERE budget IS NULL

NULL represents "unknown", so you need to use IS NULL or IS NOT NULL.

Question 4: Which executes first: SELECT or WHERE?

Click to reveal answer
Answer: WHERE executes before SELECT.

Execution order: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

Question 5: Can you use AVG() in a WHERE clause?

Click to reveal answer
Answer: No! Use HAVING for aggregate functions.

WHERE filters individual rows (before aggregation). HAVING filters grouped results (after aggregation).

Question 6: What does 10 / 4 return in SQL?

Click to reveal answer
Answer: 2 (not 2.5)

Integer division returns an integer. Use 10.0 / 4 or 10 / 4.0 to get 2.5

Question 7: What does ROUND(3456.789, -2) return?

Click to reveal answer
Answer: 3500

Negative numbers round to the left of decimal: -1 = tens, -2 = hundreds, -3 = thousands

Question 8: In GROUP BY, can you SELECT a column that's not in the GROUP BY clause?

Click to reveal answer
Answer: No, unless you use an aggregate function on it.

You can only SELECT grouped columns OR aggregates like COUNT(), SUM(), AVG(), etc.
