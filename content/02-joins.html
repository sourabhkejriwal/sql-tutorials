KEY

A column that appears in two tables and uniquely identifies each record. Think of it as a "bridge" connecting two tables.

What is INNER JOIN?

Simple Explanation: INNER JOIN fetches only the records that have matching values in BOTH tables. If there's no match, the record is excluded.

Real-world analogy: Imagine two lists - one with people's names and another with their phone numbers. INNER JOIN gives you only the people who appear on BOTH lists.

Order of Execution

1. FROM (start with left table)
2. INNER JOIN (bring in right table)
3. ON (match the keys)
4. SELECT (choose columns to display)

Question 1: Basic INNER JOIN

Task: Perform an inner join with the cities table on the left and the countries table on the right. Don't use table aliases.

Sample Data:

cities table
namecountry_codecity_proper_pop
TokyoJPN13,960,000
ParisFRA2,141,000

countries table
codenameregion
JPNJapanEast Asia
FRAFranceWestern Europe
Show Solution
SELECT *
FROM cities
INNER JOIN countries
    ON cities.country_code = countries.code;

Explanation: This joins cities and countries where the country_code in cities matches the code in countries.

Question 2: Selecting Specific Columns with Aliases

Task: Select the city name (aliased as city), country name (aliased as country), and region from the joined tables.

Show Solution
SELECT cities.name AS city, countries.name AS country, countries.region
FROM cities
INNER JOIN countries
    ON cities.country_code = countries.code;

Why use table.column notation? Both tables have a "name" column, so we must specify which table's name we want.

Question 3: Using Table Aliases

Task: Join countries (alias as c) with economies (alias as e). Select code as country_code, name, year, and inflation_rate.

Show Solution
SELECT c.code AS country_code, name, year, inflation_rate
FROM countries AS c
INNER JOIN economies AS e
    ON c.code = e.code;

Important Note

Only "code" is ambiguous (exists in both tables), so it needs a table prefix (c.code). The other columns (name, year, inflation_rate) are unique to one table, so no prefix is needed.

USING Keyword

A shortcut for the ON clause when the joining columns have the same name in both tables.

Using ON

SELECT *
FROM countries AS c
INNER JOIN languages AS l
    ON c.code = l.code;

Using USING

SELECT *
FROM countries AS c
INNER JOIN languages AS l
    USING(code);

Caution

Only use USING when the column names are IDENTICAL in both tables. If they differ (like country_code vs code), you must use ON.

Question: Finding Countries Speaking Bhojpuri

Task: Select country names and language names for all countries that speak 'Bhojpuri'. Use USING keyword.

Show Solution
SELECT c.name AS country, l.name AS language
FROM countries AS c
INNER JOIN languages AS l
    USING(code)
WHERE l.name = 'Bhojpuri';

Three Types of Relationships

1. One-to-Many (1:M)

Definition: One record in Table A relates to multiple records in Table B.

Example: One Author → Many Books (J.K. Rowling wrote Harry Potter 1, 2, 3...)

AuthorBooks
J.K. RowlingHarry Potter 1
Harry Potter 2
Harry Potter 3

2. One-to-One (1:1)

Definition: One record in Table A relates to exactly one record in Table B.

Example: One Person → One Passport, One Finger → One Fingerprint

3. Many-to-Many (M:M)

Definition: Multiple records in Table A relate to multiple records in Table B.

Example: Countries ↔ Languages (France speaks French, English; English is spoken in USA, UK, Australia...)

OUTER JOINs

Return records even if there's no match in one of the tables. The missing data appears as NULL.

LEFT JOIN

Returns: ALL records from the LEFT table + matching records from the RIGHT table

Non-matches: Show as NULL in right table columns

SELECT c1.name AS city, c2.name AS country
FROM cities AS c1
LEFT JOIN countries AS c2
    ON c1.country_code = c2.code;

RIGHT JOIN

Returns: ALL records from the RIGHT table + matching records from the LEFT table

Less Common: Most developers prefer LEFT JOIN (it's more intuitive)

LEFT JOIN ↔ RIGHT JOIN Conversion

To convert LEFT JOIN to RIGHT JOIN, you must:
1. Change JOIN type (LEFT → RIGHT)
2. Swap table order
These give the same result!

Question: Average GDP by Region

Task: Calculate average GDP per capita by region in 2010 using LEFT JOIN.

Show Solution
SELECT region, AVG(gdp_percapita) AS avg_gdp
FROM countries AS c
LEFT JOIN economies AS e
    USING(code)
WHERE year = 2010
GROUP BY c.region;

Why LEFT JOIN? We want all regions from countries, even if some don't have economic data.

FULL JOIN

Definition: Combines LEFT JOIN and RIGHT JOIN - returns ALL records from BOTH tables

Simple Explanation: "Give me everything from both tables, whether they match or not"

SELECT name AS country, region, code, basic_unit
FROM countries
FULL JOIN currencies
    USING(code)
WHERE region = 'North America' OR name IS NULL;

CROSS JOIN (Cartesian Product)

Definition: Creates ALL possible combinations between two tables

Real-world example: If you have 3 shirts and 4 pants, you have 3×4 = 12 outfit combinations

Warning

CROSS JOIN can create HUGE result sets! Use with caution.

Question: Languages in Pakistan & India

Scenario: What languages could have been spoken in Pakistan or India throughout history?

INNER JOIN (25 records)

SELECT c.name AS country, l.name AS language
FROM countries AS c
INNER JOIN languages AS l
    USING(code)
WHERE c.code IN('PAK','IND')
    AND l.code IN('PAK','IND');

CROSS JOIN (50 records)

SELECT c.name AS country, l.name AS language
FROM countries AS c
CROSS JOIN languages AS l
WHERE c.code IN('PAK','IND')
    AND l.code IN('PAK','IND');

Result: CROSS JOIN returns all combinations (2 countries × 25 languages = 50 records)

SELF JOIN

A table joined with itself to compare values within the same table

Why Use SELF JOIN?

Purpose: Compare different rows in the same table

Key Requirement: You MUST use aliases (you can't join "populations" with "populations" - you need "p1" and "p2")

Question: Population Change 2010-2015

Task: Compare each country's population in 2010 vs 2015

Show Solution
SELECT
    p1.country_code,
    p1.size AS size2010,
    p2.size AS size2015
FROM populations AS p1
INNER JOIN populations AS p2
    USING(country_code)
WHERE p1.year = 2010 AND p2.year = 2015;

How it works: We treat the populations table as TWO separate tables (p1 for 2010, p2 for 2015) and join them on country_code.

Three Set Operations

UNION | INTERSECT | EXCEPT

UNION & UNION ALL

UNION: Stacks two tables vertically, removing duplicates

UNION ALL: Stacks two tables vertically, keeping duplicates

Key Difference from JOINs

• JOINs combine tables HORIZONTALLY (add columns)
• UNION combines tables VERTICALLY (stack rows)
SELECT *
FROM economies2015
UNION
SELECT *
FROM economies2019
ORDER BY code, year;

Requirements

• Same number of columns in both queries
• Same data types in corresponding columns

INTERSECT

Returns: Only records that appear in BOTH tables

Difference from INNER JOIN: INTERSECT removes duplicates automatically

-- Find cities that are also country names
SELECT name
FROM countries
INTERSECT
SELECT name
FROM cities;

Result: Singapore (it's both a country and a city!)

EXCEPT

Returns: Records in the LEFT table that are NOT in the RIGHT table

Think of it as: "Give me everything from Table A, but remove anything that also appears in Table B"

-- Find cities that are NOT country names
SELECT name
FROM cities
EXCEPT
SELECT name
FROM countries
ORDER BY name;

Subquery

A query nested inside another query (also called an "inner query")

JOINs vs Subqueries

AspectJOINsSubqueries
PurposeCombine rows to pull data from multiple tablesFilter rows by checking if related data exists
DuplicatesCan create duplicate rowsSemi-join (IN, EXISTS) avoids duplication
Use CaseNeed columns from multiple tablesNeed to filter based on another table's data

Semi-Join (using IN)

Purpose: Filter based on existence in another table

Question: Languages in Middle East

Task: Find distinct language names spoken in Middle East countries

Show Solution
SELECT DISTINCT name
FROM languages
WHERE code IN
    (SELECT code
     FROM countries
     WHERE region = 'Middle East')
ORDER BY name;

How it works:
1. Inner query: Get all country codes in Middle East
2. Outer query: Get languages where code matches those codes

Anti-Join (using NOT IN)

Purpose: Find records that DON'T exist in another table

Question: Oceanian Countries Without Currencies

Scenario: You found 15 Oceanian currencies in an INNER JOIN, but there are 19 Oceanian countries total. Which 4 are missing?

Show Solution
SELECT code, name
FROM countries
WHERE continent = 'Oceania'
    AND code NOT IN
    (SELECT code
     FROM currencies);

Purpose: Identify data quality issues - why don't these countries have currency data?

Subqueries in SELECT

Purpose: Calculate values for each row based on the whole table

Question: High Life Expectancy Countries

Task: Find countries where 2015 life expectancy is 1.15× higher than the global average

Show Solution
SELECT *
FROM populations
WHERE year = 2015
    AND life_expectancy > 1.15 *
    (SELECT AVG(life_expectancy)
     FROM populations
     WHERE year = 2015);

Subqueries in FROM

Purpose: Create a temporary table to query from

Question: Top 10 Capital Cities by Urban Percentage

Formula: city_perc = (city_proper_pop / metroarea_pop) × 100

Filters: Europe and Americas only, capitals only, no NULL metro areas

Show Solution
SELECT name, country_code, city_proper_pop, metroarea_pop,
    city_proper_pop / metroarea_pop * 100 AS city_perc
FROM cities
WHERE name IN(
    SELECT capital
    FROM countries
    WHERE continent = 'Europe'
        OR continent LIKE '%America')
    AND metroarea_pop IS NOT NULL
ORDER BY city_perc DESC
LIMIT 10;
