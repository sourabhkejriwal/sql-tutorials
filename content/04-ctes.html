CTE (Common Table Expression)

A temporary named result set that exists only during the execution of a query. Think of it as giving a meaningful name to a subquery, making your SQL easier to read and maintain.

Basic Syntax

WITH cte_name AS (
    -- Your SELECT statement here
    SELECT column1, column2
    FROM table_name
    WHERE condition
)
-- Main query that uses the CTE
SELECT *
FROM cte_name;

Why Use CTEs?

  • Readability: Break complex queries into logical, named steps
  • Reusability: Reference the same CTE multiple times without rewriting
  • Maintainability: Easier to debug and modify
  • Temporary: Not stored in database schema, cleaned up after query execution
  • Recursion: The standard way to perform recursive queries

When to Choose a CTE

Use CTEs when:

  • Your query involves multiple steps or intermediate calculations
  • You need to work with hierarchical or tree-structured data
  • The same logic needs to be applied in multiple places within a single query
  • You want to improve readability instead of nested subqueries

Without CTE (Nested Subquery)

SELECT c.name, COUNT(sub.id)
FROM country AS c
INNER JOIN (
    SELECT country_id, id
    FROM match
    WHERE (home_goal + away_goal) >= 10
) AS sub
    ON c.id = sub.country_id
GROUP BY c.name;

Hard to read, subquery buried in JOIN

With CTE (Clean & Clear)

WITH high_scoring AS (
    SELECT country_id, id
    FROM match
    WHERE (home_goal + away_goal) >= 10
)
SELECT c.name, COUNT(h.id)
FROM country AS c
INNER JOIN high_scoring AS h
    ON c.id = h.country_id
GROUP BY c.name;

Clear intent, easy to understand!

WITH match_list AS (

        id
    FROM match
    WHERE (home_goal + away_goal) >= 10)
-- Select league and count of matches from the CTE
SELECT
    l.name AS league,
    COUNT(match_list.id) AS matches
FROM league AS l
-- Join the CTE to the league table
LEFT JOIN match_list ON l.id = match_list.country_id
GROUP BY l.name;

 2. Put the subquery logic inside parentheses
 3. Reference match_list in the main query like a table

Question 2: CTE with Calculations
Task: Create a CTE that calculates total_goals, then filter for matches with 10+ goals.
Requirements:
  • CTE should include: league name, date, home_goal, away_goal, and total_goals
  • JOIN match with league to get league names
  • Main query filters WHERE total_goals >= 10
Try it yourself
Show Solution
-- Set up your CTE
WITH match_list AS (
    -- Select the league, date, home, and away goals
    SELECT
        name AS league,
        m.date,
        m.home_goal,
        m.away_goal,
        (m.home_goal + m.away_goal) AS total_goals
    FROM match AS m
    LEFT JOIN league AS l ON m.country_id = l.id)
-- Select league, date, home, and away goals from the CTE
SELECT league, date, home_goal, away_goal
FROM match_list
-- Filter by total goals
WHERE total_goals >= 10;
Why This Works
• CTE calculates total_goals ONCE
 • Main query can reference total_goals in WHERE clause
 • Cleaner than repeating (home_goal + away_goal) in WHERE

Task:
  1. Create a CTE that calculates total goals (home + away)
  2. Use a nested subquery in WHERE to filter for August 2013/2014 matches
  3. JOIN CTE to league table
  4. Calculate AVG(goals) per league

-- Set up your CTE
WITH match_list AS (
    SELECT
        country_id,
        (home_goal + away_goal) AS goals
    FROM match
    -- Create a list of match IDs to filter data in the CTE
    WHERE id IN (
        SELECT id
        FROM match
        WHERE season = '2013/2014' AND EXTRACT(MONTH FROM date) = '08'))
-- Select the league name and average of goals in the CTE
SELECT
    name,
    AVG(match_list.goals)
FROM league AS l
-- Join the CTE onto the league table
LEFT JOIN match_list ON l.id = match_list.country_id
GROUP BY l.name;
Advanced Technique
• Nested subquery INSIDE the CTE's WHERE clause
 • EXTRACT(MONTH FROM date) gets the month number
 • Filters for month 8 (August) only

When to Use Each Method
  • JOINs: Combine columns from multiple tables based on related data
  • Nested Subqueries: Filter or calculate using one query's result in another (independent inner query)
  • Correlated Subquery: Row-by-row comparisons (dependent on outer query)
  • CTE: Complex, multi-step queries needing improved readability

Approach 1: Using Subqueries in FROM
Subquery Method
Step 1: Create home team subquery
SELECT
    m.id,
    t.team_long_name AS hometeam
-- Left join team to match
FROM match AS m
LEFT JOIN team AS t
    ON m.hometeam_id = t.team_api_id;
Step 2: Add away team subquery and combine
SELECT
    m.date,
    -- Get the home and away team names
    hometeam,
    awayteam,
    m.home_goal,
    m.away_goal
FROM match AS m

-- Join the home subquery to the match table
LEFT JOIN (
    SELECT match.id, team.team_long_name AS hometeam
    FROM match
    LEFT JOIN team
        ON match.hometeam_id = team.team_api_id) AS home
    ON home.id = m.id

-- Join the away subquery to the match table
LEFT JOIN (
    SELECT match.id, team.team_long_name AS awayteam
    FROM match
    LEFT JOIN team
        -- Get the away team ID in the subquery
        ON match.awayteam_id = team.team_api_id) AS away
    ON away.id = m.id;
Drawbacks
• Lots of nested code - hard to read
 • Repeating similar logic for home and away
 • Difficult to debug
Approach 2: Using Correlated Subqueries
Correlated Subquery Method
SELECT
    m.date,
    (SELECT team_long_name
     FROM team AS t
     WHERE t.team_api_id = m.hometeam_id) AS hometeam,
    -- Connect the team to the match table
    (SELECT team_long_name
     FROM team AS t
     WHERE t.team_api_id = m.awayteam_id) AS awayteam,
    -- Select home and away goals
    home_goal,
    away_goal
FROM match AS m;
Benefits
• More concise than nested subqueries
 • Easy to understand the correlation
 
 ⚠️ Drawbacks:
 • Runs once per row (slower for large datasets)
 • Can't reuse the subquery result
Approach 3: Using CTEs ⭐ BEST
CTE Method (Recommended!)
Step 1: Build the home CTE
SELECT
    -- Select match id and team long name
    m.id,
    t.team_long_name AS hometeam
FROM match AS m
-- Join team to match using team_api_id and hometeam_id
LEFT JOIN team AS t
    ON t.team_api_id = m.hometeam_id;
Step 2: Declare it as a CTE
-- Declare the home CTE
WITH home AS (
    SELECT m.id, t.team_long_name AS hometeam
    FROM match AS m
    LEFT JOIN team AS t
        ON m.hometeam_id = t.team_api_id)
-- Select everything from home
SELECT *
FROM home;
Step 3: Add away CTE and join them
WITH home AS (
    SELECT m.id, m.date,
        t.team_long_name AS hometeam, m.home_goal
    FROM match AS m
    LEFT JOIN team AS t
        ON m.hometeam_id = t.team_api_id),
-- Declare and set up the away CTE
away AS (
    SELECT m.id, m.date,
        t.team_long_name AS awayteam, m.away_goal
    FROM match AS m
    LEFT JOIN team AS t
        ON m.awayteam_id = t.team_api_id)
-- Select date, home_goal, and away_goal
SELECT
    home.date,
    home.hometeam,
    away.awayteam,
    home.home_goal,
    away.away_goal
-- Join away and home on the id column
FROM home
INNER JOIN away
    ON home.id = away.id;
Why CTEs Win
• Clear, named steps (home and away)
 • Easy to debug each CTE independently
 • Reusable - define once, reference multiple times
 • Much more readable than nested subqueries
 • Better performance than correlated subqueries

Multiple CTEs
You can define multiple CTEs in a single query, separated by commas. Each CTE can reference previously defined CTEs!
Syntax for Multiple CTEs
WITH
cte1 AS (
    SELECT ... FROM table1
),
cte2 AS (
    SELECT ... FROM cte1  -- Can reference cte1!
),
cte3 AS (
    SELECT ... FROM cte1 JOIN cte2  -- Can use both!
)
SELECT * FROM cte3;
Final Challenge: Complete Match Report
Goal: Create a complete match report with home team, away team, and goals using TWO CTEs!
Step-by-Step Guide
  1. Create home CTE: JOIN match and team on hometeam_id, select id, date, hometeam, home_goal
  2. Create away CTE: JOIN match and team on awayteam_id, select id, date, awayteam, away_goal
  3. Main query: JOIN both CTEs on id, select all relevant columns

Best Practices for Multiple CTEs
1. Give meaningful names (home, away, not cte1, cte2)
 2. Separate CTEs with commas
 3. Test each CTE independently before combining
 4. Document what each CTE does with comments
 5. Keep CTEs focused on one logical step each
Benefits Recap
• Modularity: Each CTE is a logical building block
 • Readability: Clear intent with meaningful names
 • Debugging: Test each CTE separately
 • Reusability: Reference CTEs multiple times if needed
 • Maintainability: Easy to modify one step without affecting others
